# Nauthilus 4.0.0-alpha.1

:::warning Upcoming prerelease

These notes prepare the upcoming `v4.0.0-alpha.1` release. They do not announce publication, deployment, or production readiness.

:::

## Breaking changes

- The Go module identity is `github.com/croessner/nauthilus/v4`.
- Native Go plugins must be rebuilt against the v4 host and exact build environment; v3 plugin binaries are not compatible.
- Top-level `policy` is the sole production configuration and runtime authority for authentication, IdP, backchannel, Policy HTTP, and Policy gRPC decisions.
- The v3 `auth.policy` root, mixed old/new roots, unqualified `standard_auth`, rule/check `stage`, and check `config_ref` are rejected.
- There is no supported converter or compatibility window. Configuration migration is manual.
- Policy and backchannel tokens have separate exact audiences and must be issued, cached, rotated, and presented independently.

## Generic Policy API

The protected HTTP contract now includes `POST /api/v1/policy/decisions` for one admitted Generic Policy evaluation. It uses Policy-specific Bearer or Basic credentials and is not owned by management/backchannel authentication.

The Nauthilus source contract contains the request, response, security, and error definitions. Synchronizing the generated website OpenAPI artifacts is a separate release dependency and is intentionally not claimed by this documentation-only preparation.

## Compatibility notes

The v4 protobuf `go_package` metadata follows the v4 module. Protobuf package names, service names, method names, message field numbers, and HTTP paths remain unchanged, so independently generated clients remain wire-compatible.

## Before testing the alpha

1. Follow the [v4 migration landing](../guides/v4-migration.md).
2. Complete the [Policy manual migration contract](../guides/policy-configuration-migration.md).
3. Rebuild native plugins against v4.
4. Regenerate Nauthilus-owned Go clients.
5. Validate the complete configuration and deployment candidate in a non-production environment.

Publication, tagging, deployment, and production rollout remain separate release actions.
