# Nauthilus 4.2 Patch Releases

This page lists the changes of the patch releases that follow [Nauthilus 4.2.0](4.2.0.md), newest first.

All patch releases keep the v4 configuration model. Read the entries between your installed version and the target
version; the items marked **Action** need an operator step.

:::note Native plugins
Rebuild every private native plugin against the exact source and Go toolchain of the release you deploy, with the
server PGO profile. `pluginapi/v1` is unchanged since 4.1.0.
:::

## 4.2.2

Published as tag `v4.2.2` on November 25, 2026. The support operations count their log windows exactly, and a window
longer than the `max_time_window` of a source is answered in parts instead of being clipped.

### Support operations and MCP

- `operational_log_overview` returned no messages with `LOKI_BUCKETS_MISALIGNED` for every window whose end was not a
  multiple of its bucket width, for example 15:38 to 16:38: a Loki query frontend aligns range evaluations to the step
  (`align_queries_with_step`), so no point met a bucket end. Every bucket is now counted by instant queries at its exact
  end, so any valid window works without rounding. This removes the known limitation of 4.2.1.
- Windows are half open, `[from, until)`. Loki counts a range as `(t-range, t]`, so counts are now evaluated one
  nanosecond before the window end: a line on the window start counts, a line on the window end does not. The
  diagnostics, the log overview, and the log events cover the same lines, and the overview buckets add up to exactly
  the lines the log events return for the same filters. The buckets tile the window; only the first may be shorter than
  `bucket_seconds`, and `LOG_BUCKETS_EXCEED_WINDOW` is gone.
- A window longer than the `max_time_window` of the Loki or Prometheus source was clipped to its newest part
  (`LOKI_WINDOW_CLIPPED`, `PROMETHEUS_WINDOW_CLIPPED`). It is now answered by up to 24 consecutive parts of at most
  `max_time_window` each, so with the default `1h` every window up to the 24-hour maximum is complete. Only a window
  that needs more than 24 parts, with a `max_time_window` below one hour, is still clipped and stated. The source
  timeout applies per part, within the 10-second budget of the call. Prometheus adds the `increase()` estimates of the
  parts, so the sum can differ by a fraction from one long increase.
- The log events read part by part, so a page can end before `limit` with a cursor at a part start. A part of which
  nothing could be read is never passed over: the page ends without a cursor, and the request can be repeated.
- Window bounds are kept in whole milliseconds, the precision of a range selector; finer digits are dropped, and the
  answer states the window it used.

See [Windows and Parts](../guides/support-mcp-access.md#windows-and-parts).

**Action:**

- None for configurations. A log overview or a long diagnostics call sends more, smaller Loki queries than before (25
  instant queries for a one-hour overview, at most four at a time). Every call keeps its fixed budget of 10 seconds,
  and the `timeout` of a source applies per part within it. If a source reports `timeout`, narrow the window or split
  it into several calls.
- Support clients that rounded overview windows to bucket boundaries can drop the workaround.

## 4.2.1

Published as tag `v4.2.1` on November 25, 2026. Support answers carry the complete stored data under the existing
scopes, two log operations make warnings and errors visible beyond the diagnostics profile, and the frontend secret is
checked by its byte length.

### Upgrade effects

- `identity.frontend.encryption_secret` must hold at least 32 bytes. The browser envelope codec needs 32 bytes, while
  the old rule counted 16 characters, so a shorter secret passed the check and the login routes failed at run time.
  An enabled frontend or IdP that cannot be built now fails the start instead of serving without login routes; the
  best-effort restart path keeps serving the other routes. See
  [Identity Reference](../configuration/idp/reference.md#frontend-encryption-secret).
- The [support history](../guides/support-authentication-history.md) returns stored values without personal masking,
  and long event and contribution lists are paged. `nauthilus:history_detail` grants nothing beyond
  `nauthilus:history_read` and is kept for existing grants. Support clients must follow the inner cursors instead of
  reading one answer as complete.

### Support operations and MCP

- `operational_log_overview` (MCP tool and `POST /api/v1/support/operations/log-overview`, scope
  `nauthilus:operations_read`) counts every WARN and ERROR message of the Loki source per level, exact message,
  instance, and time bucket. Answers state coverage, window clipping, and truncation; a counted message is an
  observation, not an incident.
- `operational_log_events` (MCP tool and `POST /api/v1/support/operations/log-events`, same scope) pages the stored Loki
  lines of a window completely: every event carries the stored line and all its fields, repeated names included.
  Paging stays stable across timestamp ties of one or many streams, and gaps are stated.
- `authentication_attempt_detail` pages the events of one attempt (`events_page`) and `bruteforce_history` the
  contributions and claimants of one ban (`inner_page`). A cursor continues after the last event id, so events stored
  more than once no longer end the paging early.
- Only authentication secrets are replaced by `<redacted>`: values of secret-named fields, labels, and assignments
  (JSON-shaped and escaped values included), Authorization and Cookie headers, URL passwords and token parameters, and
  signed tokens. Embedded JSON values are rewritten structurally as separate segments. Error texts and all other
  diagnostic data stay complete. No new scope is needed.
- An answer larger than the MCP response bound comes in segments measured on the serialized JSON-RPC response;
  `support_response_segment` (MCP tool and `POST /api/v1/support/responses/segment`) returns the next one, with a byte
  share per principal. HTTP and MCP return the same data. See
  [Read-only Support Access over MCP](../guides/support-mcp-access.md).

### Fixes

- DNS lookup errors name the ended lookup context (deadline, cancellation, or a custom cause) instead of reporting an
  expired budget as an i/o timeout; retries and the lookup budget are unchanged.
- The CI PGO refresh no longer fails on a request whose context timer fires a few milliseconds after the workload
  deadline.

### Known limitation

- The log overview can read `partial` with `LOKI_BUCKETS_MISALIGNED` and list no messages for a window whose end is
  not a multiple of the bucket width, for example 15:38 to 16:38 with five-minute buckets. The log events of the same
  window are complete. Fixed in [4.2.2](#422); in 4.2.1, end overview windows on full bucket widths.

**Action:**

- Check that `identity.frontend.encryption_secret` holds at least 32 bytes, and run `--config-check` before the
  upgrade.
- Let support clients follow `page`, `events_page`, `inner_page`, and segment cursors. MCP clients list tools when
  they connect; reconnect them to see the new tools.
- Behind a load balancer, route the segment fetches of one client to the same instance (sticky routing), because the
  segments live in the instance that produced the answer.
